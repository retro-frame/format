1. INTRODUCTION
===============================================================================


1.1 Background
-------------------------------------------------------------------------------

[RETRO-FRAME] is a Retro-Endeavor that provides [COMMON DOCUMENTATION] (i.e.
definitions, guidelines, templates and generic specifications) as well as
topic-related specifications (covered by individual repositories like this
one related to data format specifications) which are intended for use in
retrospective programming and may be used as a whole or partially for other
purposes.

The Retro-Frame Data Format Specifications comprise binary and text data
formats which may be implemented by a program (e.g. as file formats) and may
be used by other specifications.


1.2 Scope
-------------------------------------------------------------------------------

This document specifies the Retro System Specification (RSS) data format of the
type "RSS" which may be used to specify the full behavior of systems and their
components (e.g. CPU, RAM or a keyboard). It is intended that systems which are
specified in this way can be emulated.

2. OVERVIEW
===============================================================================

We undertake the very challenging task to provide a specification format which
allows to specify computer systems including their components so accurately
that they can be emulated soley based on that specification.

Although the focus is on retro systems, any system may be specified by the RSS
format as long as all relevant features are covered.

The RSS format provides a simple import mechanism which allows re-use of parts
of the entire specification (e.g. a CPU which is specified by one RSS format
and may be used by RSS formats of different systems which use that CPU).

Paths in a RSS format (e.g. for an import) are represented by universal paths
(see [COMMON DOCUMENTATION], /spec/rf-path.txt//).



3. TEXT DATA FORMAT
===============================================================================


3.1 Characteristics and character processing
-------------------------------------------------------------------------------

RSS is a not self-delimiting text format using the STANDARD CHARACTER SET.

On input, NUL characters shall be ignored but other control characters except
whitespace (including line breaks) shall be considered invalid. On output, NUL
characters should be avoided.

The following tokens are used:

- A decimal number in the range 0x00000000.. 0xFFFFFFFF, consisting of a
  sequence of up to 32 decimal digits.
- A hexadecimal number in the range 0x00000000.. 0xFFFFFFFF, consisting of a
  sequence of up to 32 hexadecimal digits ('A'..'F' may be upper- or lowercase)
  trailed by the letter 'H' (may be upper- or lowercase).
- An identifier of up to 32 characters. Lowercase letters shall implicitly be
  converted to uppercase letters. Note that identifiers may start with a digit.
- A string, enclosed in double-quotes, of up to 255 characters (excluding the
  double-quoted). No line break shall occur in a string. Escape character is
  the reverse solidus ('\'). Currently, only the double-quotes are defined as
  an escape sequence.
- The following symbols: ",", ".", ":", "+", "-", "*", "/", "%", "==", "!=",
  "<", "<=", ">", ">=", "<>", "=", "+=", "-=", "*=", "/=", "%=", "&=", "|=",
  "^=", "&", "|", "^", "~", "&&", "||", "^^", "!", "?", "<<", "<<<", ">>",
  ">>>", "(", ")", "[", "]", "{" and "}".

Two consecutive identifiers must be separated by whitespace if the leading
identifier does not have a trailing single-quote ''' and the successing
identifier does not have a leading dollar-sign '$'. Symbols which consist of
more than one character are parsed in a way that alwayse the longest token is
recognized (e.g. "<<=" is parsed as "<<" and "=" rather than "<" and "<=").

There are no restrictions on the format version.


3.2 Syntax of version 1.0
-------------------------------------------------------------------------------

<rss-format-identifier>:

  "RSS/1.0"

<rss-ws>:

  ( WS | [ ";" [ . | WS ]* ] LB )*

<rss-dec-number>:

  9 [_9 ]*

<rss-hex-number>:

  ( X_)*_"H"

<rss-bit>:

  "0" | "1" | A

<rss-bit-mask>:

  <rss-bit> [_<rss-bit> ]*

<rss-string-escape>:

  """"

<rss-string>:

  """"_[_._|_"\"_<rss-string-escape>_|_WS_]* """"

<rss-label>:

  <rss-string>

<rss-identifier>:

  ( "$" | A | 9 | "_" ) [_A |_9 |_"_" ]* [ "'" ]

<rss-import>:

  "IMPORT" <universal-path> "."

<rss-data-bus>:

  <rss-identifier> "/" <rss-number>

<rss-non-data-bus>:

  <rss-identifier>

<rss-bus>:

  <rss-data-bus> | <rss-non-data-bus>

<rss-bus-list>:

  "(" <rss-bus> [ "," <rss-bus> ]* ")"

<rss-block-header>:

  <rss-label> [ <rss-bus-list> ]

<rss-statement>:

  (TO DO)

<rss-opcode-event>:

  "OPCODE" [ <rss-bit-mask> ]*

<rss-key-event>:

  "KEY" [ "PRESSED" | "RELEASED" ] [ <rss-bit-mask> ]*

<rss-bus-event>:

  <rss-identifier> [ "READ" | "WRITE" ] [ <rss-bit-mask> ]

<rss-standard-event>:

  "INIT" | "DONE" | "RESET" | <rss-bus-event>

<rss-cpu-event>:

  <rss-standard-event> | <rss-opcode-event>

<rss-cpu-section>:

  <rss-cpu-event> ":" [ <rss-statement> ]*

<rss-cpu>:

  "CPU" <rss-block-header> "{" [ <rss-cpu-section> ]* "}"

<rss-rom-section>:

  <rss-standard-event> ":" [ <rss-statement> ]*

<rss-rom>:

  "ROM" <rss-block-header> "{" [ <rss-rom-section> ]* "}"

<rss-ram-section>:

  <rss-standard-event> ":" [ <rss-statement> ]*

<rss-ram>:

  "RAM" <rss-block-header> "{" [ <rss-ram-section> ]* "}"

<rss-keyboard-event>:

  <rss-standard-event> | <rss-key-event>

<rss-keyboard-section>:

  <rss-keyboard-event> ":" [ <rss-statement> ]*

<rss-keyboard>:

  "KEYBOARD" <rss-block-header> "{" [ <rss-keyboard-section> ]* "}"

<rss-screen-section>:

  <rss-standard-event> ":" [ <rss-statement> ]*

<rss-screen>:

  "SCREEN" <rss-block-header> "{" [ <rss-screen-section> ]* "}"

<rss-component>:

  <rss-block-header> "{" [ <rss-component-section> ]* "}"

<rss-component-type>:

  "CPU" | "ROM" | "RAM" | "KEYBOARD" | "SCREEN"

<rss-system-component>:

  <rss-component-type> <rss-label> [ <rss-bus-list> ] "."

<rss-system>:

  "SYSTEM" <rss-block-header> "{" [ <rss-system-component> ]* "}"

<rss-body>:

  [ <rss-import> | <rss-component> | <rss-system> ]*

<rss-header>:

  [ <rf-skip-element>_]* ( LB | "??" )

<rss>:

  <rss-format-identifier>_<rss-header>_<rss-body>


3.3 Semantics
-------------------------------------------------------------------------------
