3.1 LZ77 compression
-------------------------------------------------------------------------------

The initial processing of the input data (given as a UINT-8 sequence of bytes)
is an algorithm which identifies identical sequences of a length from 3 to 258
bytes within a sliding window of 32768 bytes according to the LZ77 compression
(Lempel-Ziv 1977, the algorithms are not subject to this description of the
data format):

                          +------------------------------+
                          |  32768 bytes sliding window  |
  +-----------------------+------------------------------+------------------+
  |  input data (UINT-8)                 <length>         <length>          |
  +--------------------------------------^----------------^-----------------+
                                         |    distance    | current index
                                         +----------------+

The position of the identical sequence within the sliding window is referenced
by the backward distance relative to the current index (i.e. the byte preceding
the current index has distance 1 and the maximum distance is 32768). Within the
first 32767 bytes of the input data, the sliding window must be clipped (i.e.
the distance must not exceed the input data). While the sequence must start
within the sliding window, it may overlap with the identical sequence starting
from the current index.

All references to identical sequences, given by the triple

  (index, distance, length)

are intermediate information at this stage and may be stored at discretion. No
more than one reference shall exist for each index. If more than one sequence
was found in the sliding window, the longest sequence should be chosen (if the
maximum length was found multiple times, the smallest distance should be
favored).

Example:

  index  input data (hex)  distance  length  comment
  -----  ----------------  --------  ------  --------------------------------
      0                00       n/a     n/a  identical sequence not possible
      1                01       n/a     n/a  no identical sequence
      2                AA       n/a     n/a  no identical sequence
      3                BB       n/a     n/a  no identical sequence
      4                00       n/a     n/a  sequence 00 01 is too short
      5                01       n/a     n/a  sequence 01 is too short
      6                AF       n/a     n/a  no identical sequence
      7                00         3       5  sequence 00 01 AF 00 01 overlaps
      8                01       n/a     n/a  part of identical sequence
      9                AF       n/a     n/a  part of identical sequence
     10                00       n/a     n/a  part of identical sequence
     11                01       n/a     n/a  part of identical sequence
     12                BE       n/a     n/a  no identical sequence
     13                00         6       3  favor smaller distance
     14                01       n/a     n/a  part of identical sequence
     15                AF       n/a     n/a  part of identical sequence
     16                FF       n/a     n/a  no identical sequence

  As a result, the identical sequences are (7, 3, 5) and (13, 6, 3).

Note that LZ77 compression is always performed on the entire input data, even
if the data is processed in smaller buffers and regardless of the block format
determined later (see chapter 3.4). However, no references to other input data
must be used, even if other input data immediately preceding may be given (e.g.
in a file).

On compression, in order to comply with the data format, it is not required to
find all or the optimal identical sequences (thus, a smaller sliding window may
be chosen and in worst case, no identical sequences are found at all). However,
on decompression, the full sliding window must be supported.


3.2 Representation by codes and extra bits
-------------------------------------------------------------------------------

On the next stage, the result of the LZ77 compression is represented as codes
considering the identical sequences found before (see chapter 3.1):

- Codes 0..255 represent the corresponding original value (i.e. 0x00..0xFF) of
  a single byte of the input data and are called literal codes.

- Code 256 is an end marker and reserved on this stage (see capter 3.4).

- Codes 257..285 represent a reference to an identical sequence where the code
  depends on the length of the triple (index, distance, length) and the codes
  are thus called length codes.

If a part of the input data is represented by a reference to an identical
sequence, the corresponding 3 to 258 bytes are omitted (i.e. each part of the
input data is represented by either a literal code or a length code).

While the literal codes are sufficient to represent a single byte of the input
data, references to identical sequences are indicated by a length code in the
range 257..285 but need further representation:

- For codes in the range 265..284, the lengths are subtracted by a fixed offset
  and represented by a fixed number of extra bits in big-endian order.

- The distance of the triple (index, distance, length) is represented by a
  second code in the range 0..29 which is called the distance code.

- For distance codes in the range 4..29, the distances are subtracted by a
  fixed offset and represented by a fixed number of extra bits in big-endian
  order.

Thus, a reference to an identical sequence is represented by the sequence

  <length-code> <length-extra-bits> <distance-code> <distance-extra-bits>

The following table specifies the length codes and length extra bits:

  length range  length code range  extra bits  length offset
  ------------  -----------------  ----------  -----------------------
         3..10           258..264           0  3 + code - 258
        11..18           265..268           1  11 + (code - 265) * 2
        19..34           269..272           2  19 + (code - 269) * 4
        35..66           273..276           3  35 + (code - 273) * 8
       67..130           277..280           4  67 + (code - 277) * 16
      131..257           281..284           5  131 + (code - 281) * 32
           258                285           0  n/a

The length code can be determined by the maximum code where length >= length
offset (e.g. length 34 matches code 272 with length offset 19 + (272 - 269) * 4
= 31 but not 273 with length offset 35 + (273 - 273) * 8 = 35).

The following table specifies the distance codes and distance extra bits:

  distance range  distance code range  extra bits  distance offset
  --------------  -------------------  ----------  --------------------------
            1..4                 0..3           0  1 + code
            5..8                 4..5           1  5 + (code - 4) * 2
           9..16                 6..7           2  9 + (code - 6) * 4
          17..32                 8..9           3  17 + (code - 8) * 8
          33..64               10..11           4  33 + (code - 10) * 16
         65..128               12..13           5  65 + (code - 12) * 32
        129..256               14..15           6  129 + (code - 14) * 64
        257..512               16..17           7  257 + (code - 16) * 128
       513..1024               18..19           8  513 + (code - 18) * 256
      1025..2048               20..21           9  1025 + (code - 20) * 512
      2049..4096               22..23          10  2049 + (code - 22) * 1024
      4097..8192               24..25          11  4097 + (code - 24) * 2048
     8193..16384               26..27          12  8193 + (code - 26) * 4096
    16385..32768               28..29          13  16385 + (code - 28) * 8192

The distance code can be determined by the maximum code where distance >=
distance offset (e.g. distance 195 matches code 15 with distance offset 129 +
(15 - 14) * 64 = 193 but not 16 with distance offset 257 + (16 - 16) * 128 =
257).

Example:

  The LZ77 compressed data in the example of chapter 3.1 would be represented
  by the following codes and extra bits (only distant extra bits occur here):

  index  literal / length code  distance code  extra bits  part of input data
  -----  ---------------------  -------------  ----------  ------------------
      0                      0            n/a         n/a  00
      1                      1            n/a         n/a  01
      2                    170            n/a         n/a  AA
      3                    187            n/a         n/a  BB
      4                      0            n/a         n/a  00
      5                      1            n/a         n/a  01
      6                    175            n/a         n/a  AF
      7                    259              2         n/a  00 01 AF 00 01
     12                    190            n/a         n/a  BE
     13                    258              4           1  00 01 AF
     16                    255            n/a         n/a  FF

  For example, the input data sequence 00 01 AF at index 13 is represented by
  the length code 258 (indicating a length of 3 without needing any extra bits)
  and the distance code 4 (indicating a distance offset of 5), followed by a
  single extra bit of value 1 which is added to the distance offset resulting
  in a distance of 6.
